BUILT TO BE QUESTIONED
Method & limits
Understand what this service measures, and what it cannot establish.
A bounded extension
This capstone extends the existing Provenance Guard repository. Shape A adds the local run path, structured request traces, stage timing and measured runtime cost. The detector, weights, thresholds and appeal workflow are preserved.
How a label is produced
The combined index is 0.7 × model signal + 0.3 × style signal. A score at or below 0.20 maps to human, at or above 0.80 to AI, and everything between to unsure. If signals differ by at least 0.5, the combined index is clamped to 0.35–0.65.
Latency and CPU
Wall time includes time waiting during a request. CPU time measures process compute consumed. This local deployment serves one request at a time so the CPU measurement is attributable. Trace-file write time and network transfer are excluded from server timing; the evaluation runner separately measures client latency.
Predictability is not authorship
Plain language, second-language writing and repeated phrases can produce false flags. Unusual AI prose can evade detection. These indices are uncalibrated heuristics and must not be used as sole evidence for discipline or attribution.
Your data stays local
No hosted inference API is used. GPT-2 may download about 550 MB at first use. Request traces retain lengths and hashes rather than submitted prose; the existing audit still retains creator IDs, decisions and appeal reasons. The dashboard is unauthenticated and bound to loopback.
Scope of the evidence
Dashboard metrics summarize persisted traces, not accuracy or all-time traffic. Reading the dashboard does not create telemetry. Cost evidence, before/after trials and AI assistance disclosures live in the repository README.
